AWS DevOps -pikakurssi

Terraformilla rakennettava infrastruktuuri Python-, Django-/FastAPI-, Next.js-, PostgreSQL- ja Docker-sovelluksille.

1. Johdanto ja pelisäännöt

AWS on pilvipalveluiden lauta, jolla on satoja palveluita. DevOpsissa et tarvitse kaikkia. Tämä kurssi keskittyy palveluihin, joilla yleisin web-sovellus saadaan pystyyn: verkko, tietokanta, konttien ajo, kuormantasaus, tiedostot, DNS ja automaatio.

Kolme käsitettä kannattaa hallita heti:

  • Region: maantieteellinen alue, esim. eu-north-1 (Tukholma), joka on Suomesta lähin. Palvelut ja resurssit ovat aina tietyssä regionissa.
  • Availability Zone (AZ): regionin sisäinen erillinen datakeskus. Redundanssi rakennetaan levittämällä resursseja useaan AZ:hen.
  • Account: laskutus- ja oikeusrajan muodostava tili. Käytä erillistä tiliä kehitykselle ja tuotannolle.

Kustannus- ja turvallisuusvaroitus

Pilvi laskuttaa käytöstä, ei siitä, että palvelu on "pystyssä" tyhjäkäynnillä. Erityisen kalliita ovat NAT Gateway, Application Load Balancer ja RDS, jotka maksavat myös silloin, kun niitä ei käytetä.

  • Aseta laskutushälytys heti (AWS Budgets, esim. 10 €/kk).
  • Kokeile aina terraform plan ennen apply-komentoa.
  • Opettelun jälkeen aja terraform destroy, ettet jätä resursseja pyörimään.
  • Älä koskaan kirjoita avaimia koodiin tai tiedostoihin. Käytä IAM-rooleja ja Secrets Manageria.

Kurssin palvelukartta

Tyypillinen web-sovellus näyttää tältä:

Käyttäjä → Route 53 (DNS) → ACM (TLS) → ALB (kuormantasaus)
                                            ↓
                              ECS Fargate (Docker-kontit: Django / FastAPI / Next.js)
                                            ↓                    ↓
                                 RDS PostgreSQL          Secrets Manager
                                            
Staattiset tiedostot: S3 → CloudFront → käyttäjä
Lokit ja mittarit: CloudWatch
Koodi ja kuvat: GitHub → GitHub Actions (OIDC) → ECR → ECS

2. Terraform-perusta

Mitä se on: Terraform on infrastructure as code (IaC) -työkalu. Kuvaat infrastruktuurin HCL-kielisinä tiedostoina, ja Terraform vertaa kuvausta todelliseen tilaan (state) ja tekee tarvittavat muutokset.

Liittyy muihin: AWS Provider, S3 (state-tiedosto), DynamoDB (lukitus), CI/CD-putket.

Mihin sitä käytetään ja miksi

  • Infrastruktuuri on toistettava: sama koodi tuottaa saman ympäristön kehitykseen, testiin ja tuotantoon.
  • Muutokset näkyvät versionhallinnassa ja niistä voi tehdä katselmoinnin pull requestilla.
  • Konsoliklikkailu ei skaalaudu eikä jää dokumentoiduksi. Koodi on dokumentaatio.
  • plan-vaihe näyttää etukäteen, mitä muuttuu, ja vähentää yllätyksiä.

Perusrakenne ja tilan tallennus

terraform {
  required_version = ">= 1.6"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  # Tila tallennetaan S3:een, jotta se ei ole vain yhden koneen varassa
  backend "s3" {
    bucket         = "toni-tfstate"
    key            = "devops-demo/terraform.tfstate"
    region         = "eu-north-1"
    dynamodb_table = "tf-locks"   # estää kaksi samanaikaista apply-ajoa
    encrypt        = true
  }
}

provider "aws" {
  region = "eu-north-1"
  # Tagit kaikille resursseille automaattisesti (kustannusseuranta!)
  default_tags {
    tags = {
      Project   = "devops-demo"
      ManagedBy = "terraform"
    }
  }
}

Vinkki: Tila (terraform.tfstate) voi sisältää arkaluontoista dataa. Älä koskaan committaa sitä Gitiin. Käytä S3-backendia ja salaa se.

3. IAM (Identity and Access Management)

Mitä se on: IAM hallitsee, kuka tai mikä saa tehdä mitä AWS:ssä. Peruskäsitteet ovat käyttäjät (users), ryhmät, roolit (roles) ja politiikat (policies). Politiikka on JSON-dokumentti, joka sallii tai kieltää toimintoja.

Liittyy muihin: kaikki palvelut. ECS tarvitsee roolin kuvien hakuun, Lambda roolin lokeihin, GitHub Actions roolin deployyn varten.

Mihin sitä käytetään ja miksi

  • Vähimmän oikeuden periaate: jokainen palvelu saa vain ne oikeudet, joita se tarvitsee. Jos sovellus vuotaa, vahinko rajoittuu.
  • Roolit palveluille: ECS-tehtävä ei tarvitse käyttäjätunnusta. Se ottaa roolin ja saa väliaikaiset tunnukset.
  • Ei pitkäaikaisia avaimia: roolit ja OIDC poistavat tarpeen tallentaa AWS-avaimia CI-palveluun.

Esimerkki: palveluroolin luominen

data "aws_iam_policy_document" "ecs_assume" {
  statement {
    actions = ["sts:AssumeRole"]
    principals {
      type        = "Service"
      identifiers = ["ecs-tasks.amazonaws.com"]
    }
  }
}

resource "aws_iam_role" "ecs_execution" {
  name               = "demo-ecs-execution"
  assume_role_policy = data.aws_iam_policy_document.ecs_assume.json
}

# AWS:n valmis politiikka: kuvien veto ECR:stä ja lokien kirjoitus
resource "aws_iam_role_policy_attachment" "ecs_execution" {
  role       = aws_iam_role.ecs_execution.name
  policy_arn = "arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy"
}

Vältä "Action": "*" ja "Resource": "*" -yhdistelmää. Se on käytännössä admin-oikeus, ja se on yleisin syy vuotoihin.

4. VPC ja verkko

Mitä se on: VPC (Virtual Private Cloud) on oma eristetty verkkosi AWS:ssä. Sen sisällä on aliverkkoja (subnet), reititystauluja, Internet Gateway (IGW) ja NAT Gateway. Security Group toimii palomuurina resurssin tasolla.

Liittyy muihin: lähes kaikki: RDS, ECS, ALB, EC2, Lambda (VPC-kytkettynä).

Mihin sitä käytetään ja miksi

  • Julkinen ja yksityinen eristys: ALB on julkisessa aliverkossa, tietokanta ja sovelluskontit yksityisessä. Tietokantaa ei voi tavoittaa internetistä edes vahingossa.
  • Usean AZ:n redundanssi: kaksi aliverkkoa eri AZ:issa, jotta yksi datakeskuksen vika ei kaada palvelua.
  • Security Groupit: sallitaan vain tarvittava liikenne, esim. ALB → sovellus porttiin 8000, sovellus → tietokanta porttiin 5432.

Esimerkki: VPC, aliverkot ja reititys

resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
  tags                 = { Name = "demo-vpc" }
}

data "aws_availability_zones" "available" {
  state = "available"
}

resource "aws_subnet" "public" {
  count                   = 2
  vpc_id                  = aws_vpc.main.id
  cidr_block              = cidrsubnet(aws_vpc.main.cidr_block, 8, count.index)
  availability_zone       = data.aws_availability_zones.available.names[count.index]
  map_public_ip_on_launch = true
  tags                    = { Name = "public-${count.index}" }
}

resource "aws_subnet" "private" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 8, count.index + 10)
  availability_zone = data.aws_availability_zones.available.names[count.index]
  tags              = { Name = "private-${count.index}" }
}

resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}

resource "aws_route_table_association" "public" {
  count          = 2
  subnet_id      = aws_subnet.public[count.index].id
  route_table_id = aws_route_table.public.id
}

# Security group ALB:lle: sallii HTTP ja HTTPS internetistä
resource "aws_security_group" "alb" {
  name   = "demo-alb"
  vpc_id = aws_vpc.main.id
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# Sovellus hyväksyy liikennettä vain ALB:ltä
resource "aws_security_group" "app" {
  name   = "demo-app"
  vpc_id = aws_vpc.main.id
  ingress {
    from_port       = 8000
    to_port         = 8000
    protocol        = "tcp"
    security_groups = [aws_security_group.alb.id]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

Kustannusvinkki: Yksityisistä aliverkoista pääsy internetiin (esim. kuvien veto ulkopuolelta) vaatii NAT Gatewayn, joka maksaa kiinteän hinnan kuukaudessa. Kurssiesimerkissä sovellus ajetaan julkisessa aliverkossa, mutta tietokanta pysyy yksityisessä. Tuotannossa NAT on yleensä perusteltu.

5. ECR (Elastic Container Registry)

Mitä se on: AWS:n yksityinen Docker-rekisteri. Tallennat siihen sovelluksesi kontti-imagen, ja ECS, Lambda tai EKS hakevat imagen sieltä.

Liittyy muihin: ECS, Lambda, EKS, CodeBuild, GitHub Actions, IAM.

Mihin sitä käytetään ja miksi

  • Imagen versiointi: jokainen build saa tagin (esim. git-commit-hash), jolloin tiedät tarkalleen mikä koodi on tuotannossa.
  • Turvallisuus: automaattinen haavoittuvuusskannaus (scan_on_push) kertoo riippuvuuksien ongelmista.
  • Lähellä kuormaa: saman alueen sisällä imagen veto on nopeaa eikä vie internet-kaistaa.

Esimerkki

resource "aws_ecr_repository" "app" {
  name                 = "devops-demo"
  image_tag_mutability = "IMMUTABLE"   # sama tagi ei voi ylikirjoittua

  image_scanning_configuration {
    scan_on_push = true
  }
}

# Elinkaarisääntö: pidetään vain 10 viimeisintä imagea, jotta tila ei kasva
resource "aws_ecr_lifecycle_policy" "app" {
  repository = aws_ecr_repository.app.name
  policy = jsonencode({
    rules = [{
      rulePriority = 1
      description  = "Pidä 10 viimeisintä"
      selection = {
        tagStatus   = "any"
        countType   = "imageCountMoreThan"
        countNumber = 10
      }
      action = { type = "expire" }
    }]
  })
}

Docker-kuvan rakentaminen ja työntäminen: aws ecr get-login-password --region eu-north-1 | docker login --username AWS --password-stdin <tili>.dkr.ecr.eu-north-1.amazonaws.com, sitten docker build -t devops-demo . ja docker push.

6. Secrets Manager ja SSM Parameter Store

Mitä se on: Secrets Manager tallentaa salaisuuksia (salasanat, API-avaimet) salattuna ja kierrättää niitä automaattisesti. SSM Parameter Store on kevyempi vaihtoehto, joka sopii myös ei-salaisille asetuksille.

Liittyy muihin: RDS (automaattinen salasanan hallinta), ECS (secrets-kenttä), Lambda, KMS (salausavaimet).

Mihin sitä käytetään ja miksi

  • Ei salaisuuksia koodissa tai ympäristömuuttujissa: sovellus hakee arvon ajon aikana tai ECS hakee sen käynnistyksessä.
  • Kierrätys: salasanan vaihto ilman sovelluksen uudelleenjulkaisua.
  • Audit: CloudTrail kirjaa, kuka on lukenut salaisuuden.

Esimerkki: parametri ja salaisuus

resource "aws_ssm_parameter" "debug" {
  name  = "/devops-demo/DJANGO_DEBUG"
  type  = "String"
  value = "0"
}

resource "aws_secretsmanager_secret" "api_key" {
  name                    = "devops-demo/third-party-api-key"
  recovery_window_in_days = 7
}

# Arvo asetetaan Terraformin ulkopuolella, jotta se ei päädy tilaan:
# aws secretsmanager put-secret-value --secret-id devops-demo/third-party-api-key --secret-string "..."

Terraform tallentaa resurssien arvot tila-tiedostoon. Jos kirjoitat salasanan suoraan value-kenttään, se päätyy tilaan. Käytä RDS:n manage_master_user_password-asetusta tai aseta arvo erikseen (kuten yllä).

7. RDS (Relational Database Service) PostgreSQL

Mitä se on: Hallittu relaatiotietokanta. AWS hoitaa asennuksen, varmuuskopiot, version päivitykset ja korkean saatavuuden. Sinä kirjoitat skeeman ja kyselyt.

Liittyy muihin: VPC (yksityinen aliverkko), Security Groups, Secrets Manager, CloudWatch (mittarit), ECS/Lambda (asiakkaat). Geospatiaaliseen työhön: PostGIS on tuettu.

Mihin sitä käytetään ja miksi

  • Varmuuskopiot ja palautus: automaattiset snapshotit ja pistekohtainen palautus (point-in-time recovery). Itse ylläpidettynä tämä on työlästä.
  • Monivyöhykkeinen (Multi-AZ): synkroninen varakopio toisessa AZ:ssa, automaattinen failover.
  • Skaalaus: instanssiluokan vaihto tai luku-replikat raskaalle lukukuormalle.
  • Kehityksen Docker-vastine: tuotannon kaltainen PostgreSQL ilman, että sitä tarvitsee ylläpitää itse.

Esimerkki

resource "aws_db_subnet_group" "db" {
  name       = "demo-db"
  subnet_ids = aws_subnet.private[*].id
}

resource "aws_security_group" "db" {
  name   = "demo-db"
  vpc_id = aws_vpc.main.id
  ingress {
    from_port       = 5432
    to_port         = 5432
    protocol        = "tcp"
    security_groups = [aws_security_group.app.id]   # vain sovellus pääsee
  }
}

resource "aws_db_instance" "postgres" {
  identifier              = "demo-postgres"
  engine                  = "postgres"
  engine_version          = "16"
  instance_class          = "db.t4g.micro"
  allocated_storage       = 20
  max_allocated_storage   = 100          # automaattinen kasvu
  db_name                 = "appdb"
  username                = "appuser"
  manage_master_user_password = true     # AWS luo salasanan Secrets Manageriin
  db_subnet_group_name    = aws_db_subnet_group.db.name
  vpc_security_group_ids  = [aws_security_group.db.id]
  storage_encrypted       = true
  publicly_accessible     = false
  backup_retention_period = 7
  multi_az                = false        # tuotannossa true
  skip_final_snapshot     = true         # tuotannossa false
  deletion_protection     = false        # tuotannossa true
}

Django/FastAPI: sovelluksen DATABASE_HOST on RDS:n address-attribuutti (aws_db_instance.postgres.address), ja salasana haetaan Secrets Manageristä. Paikallisessa Docker Composessa sama rakenne toimii, vain host vaihtuu.

8. ECS Fargate (Docker-kontit ilman palvelimia)

Mitä se on: ECS (Elastic Container Service) ajaa Docker-kontteja. Fargate-tilassa et hallitse palvelimia lainkaan: määrittelet kontin koon ja määrän, AWS ajaa sen. Vaihtoehtoja ovat EC2-pohjainen ECS ja EKS (Kubernetes). Yksinkertaisuuden vuoksi Fargate on oikea valinta useimmille web-sovelluksille.

Liittyy muihin: ECR (imaget), ALB (liikenne), CloudWatch (lokit), IAM (tehtäväroolit), Secrets Manager, VPC.

Mihin sitä käytetään ja miksi

  • Sovelluksen ajo konteissa: sama Docker-image toimii kehityksessä ja tuotannossa, ja kontit voi ajaa useana kopiona.
  • Automaattinen palautuminen: ECS käynnistää kuolleen kontin uudelleen ja ylläpitää haluttua määrää (desired_count).
  • Rolling deploy: uusi versio käynnistyy vanhan rinnalle, ja liikenne siirtyy vasta terveenä. Virheen sattuessa vanha versio pysyy.
  • Ei palvelinhallintaa: ei käyttöjärjestelmäpäivityksiä, ei kapasiteettisuunnittelua.

Esimerkki: tehtävämääritys ja palvelu

resource "aws_cloudwatch_log_group" "app" {
  name              = "/ecs/devops-demo"
  retention_in_days = 14
}

# Tehtäväroolin on saatava lukea salaisuus RDS:n salasanaa varten
resource "aws_iam_role_policy" "ecs_read_db_secret" {
  name = "read-db-secret"
  role = aws_iam_role.ecs_execution.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["secretsmanager:GetSecretValue"]
      Resource = aws_db_instance.postgres.master_user_secret[0].secret_arn
    }]
  })
}

resource "aws_ecs_cluster" "main" {
  name = "demo-cluster"
}

resource "aws_ecs_task_definition" "app" {
  family                   = "devops-demo"
  requires_compatibilities = ["FARGATE"]
  network_mode             = "awsvpc"
  cpu                      = 256
  memory                   = 512
  execution_role_arn       = aws_iam_role.ecs_execution.arn

  container_definitions = jsonencode([{
    name         = "app"
    image        = "${aws_ecr_repository.app.repository_url}:latest"
    essential    = true
    portMappings = [{ containerPort = 8000, protocol = "tcp" }]

    environment = [
      { name = "DATABASE_HOST", value = aws_db_instance.postgres.address },
      { name = "DATABASE_NAME", value = "appdb" },
      { name = "DJANGO_DEBUG",  value = "0" }
    ]

    # JSON-avain "password" salaisuuden sisällä
    secrets = [{
      name      = "DATABASE_PASSWORD"
      valueFrom = "${aws_db_instance.postgres.master_user_secret[0].secret_arn}:password::"
    }]

    logConfiguration = {
      logDriver = "awslogs"
      options = {
        "awslogs-group"         = aws_cloudwatch_log_group.app.name
        "awslogs-region"        = "eu-north-1"
        "awslogs-stream-prefix" = "app"
      }
    }
  }])
}

resource "aws_ecs_service" "app" {
  name            = "devops-demo"
  cluster         = aws_ecs_cluster.main.id
  task_definition = aws_ecs_task_definition.app.arn
  desired_count   = 2
  launch_type     = "FARGATE"

  network_configuration {
    subnets          = aws_subnet.public[*].id
    security_groups  = [aws_security_group.app.id]
    assign_public_ip = true   # tarvitaan ECR:n vetoon ilman NAT:ia
  }

  load_balancer {
    target_group_arn = aws_lb_target_group.app.arn
    container_name   = "app"
    container_port   = 8000
  }

  depends_on = [aws_lb_listener.http]
}

Next.js: sama malli toimii Next.js-kontille. Vaihda portti 3000:een ja käytä output: "standalone"-asetusta, jolloin imagesta tulee pieni. Frontendin staattiset assetit voi tarjota CloudFront-S3-yhdistelmällä (katso CloudFront-osio).

Yllä olevassa esimerkissä tehtävät ovat julkisessa aliverkossa julkisella IP:llä, mutta Security Group sallii liikenteen vain ALB:ltä. Tuotannossa suositus on yksityinen aliverkko + NAT.

9. ALB (Application Load Balancer)

Mitä se on: Kuormantasaaja, joka ymmärtää HTTP-tason. Se jakaa pyynnöt terveille kohteille (target group), päättää TLS:n ja voi reitittää polkujen perusteella (esim. /api/* Djangolle, muu Next.js:lle).

Liittyy muihin: ECS, ACM (TLS-sertifikaatit), Route 53 (DNS), Security Groups, CloudWatch.

Mihin sitä käytetään ja miksi

  • Terveyden tarkistus: ALB poistaa kontit, jotka eivät vastaa /health/-polkuun, joten rikkinäinen versio ei saa liikennettä.
  • Nollakatkoinen deploy: uusi ECS-tehtävä rekisteröityy kohderyhmään vasta, kun se on terve.
  • TLS-päätepiste: sertifikaatti on ALB:llä, sovellus voi puhua HTTP:tä sisäverkossa.
  • Polkureititys: yksi domain, useita palveluita (monoliitti vs. API + frontend).

Esimerkki

resource "aws_lb" "app" {
  name               = "demo-alb"
  load_balancer_type = "application"
  subnets            = aws_subnet.public[*].id
  security_groups    = [aws_security_group.alb.id]
}

resource "aws_lb_target_group" "app" {
  name        = "demo-tg"
  port        = 8000
  protocol    = "HTTP"
  vpc_id      = aws_vpc.main.id
  target_type = "ip"              # Fargate käyttää IP-osoitteita

  health_check {
    path                = "/health/"
    healthy_threshold   = 2
    unhealthy_threshold = 3
    interval            = 15
  }
}

resource "aws_lb_listener" "http" {
  load_balancer_arn = aws_lb.app.arn
  port              = 80
  protocol          = "HTTP"

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.app.arn
  }
}

Tuotannossa lisää HTTPS-kuuntelija (port 443) ACM-sertifikaatilla ja ohjaa HTTP → HTTPS. Sertifikaatti käsitellään seuraavassa Route 53 ja ACM -osiossa.

10. CloudWatch (lokit, mittarit, hälytykset)

Mitä se on: Havainnointipalvelu. Kerää lokit (Logs), mittarit (Metrics), hälytykset (Alarms) ja hallintapaneelit (Dashboards).

Liittyy muihin: lähes kaikki AWS-palvelut tuottavat mittareita. ECS, Lambda, RDS, ALB.

Mihin sitä käytetään ja miksi

  • Vianetsintä: sovelluksen stdout-loki näkyy ilman SSH-yhteyttä palvelimelle.
  • Hälytykset: esim. ALB:n 5xx-virheet tai RDS:n CPU yli 80 %. Hälytys voi lähettää SNS:n kautta sähköpostin tai Slackiin.
  • Kustannushallinta: lokeille voi asettaa säilytysajan (retention_in_days), muuten lokit kertyvät ja maksavat.

Esimerkki: hälytys ALB:n virheille

resource "aws_sns_topic" "alerts" {
  name = "devops-demo-alerts"
}

resource "aws_cloudwatch_metric_alarm" "alb_5xx" {
  alarm_name          = "demo-alb-5xx-high"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 2
  metric_name         = "HTTPCode_Target_5XX_Count"
  namespace           = "AWS/ApplicationELB"
  period              = 60
  statistic           = "Sum"
  threshold           = 10
  dimensions = {
    LoadBalancer = aws_lb.app.arn_suffix
  }
  alarm_actions = [aws_sns_topic.alerts.arn]
}

11. S3 (Simple Storage Service)

Mitä se on: Objektitallennus. Tallennat tiedostoja "bucketeihin" avaimen (polun) perusteella. Kestävyys on erittäin korkea ja kapasiteetti käytännössä rajaton.

Liittyy muihin: CloudFront (jakelu), Lambda (tapahtumat), Athena (SQL tiedostoille), Glue (datakatalogi), Terraform (state), ECS (tiedostolataukset).

Mihin sitä käytetään ja miksi

  • Django-median ja staattisten tiedostojen tallennus: tiedostot eivät katoa, kun kontti uusitaan. Kontit ovat väliaikaisia, S3 ei ole.
  • Next.js-buildin staattiset assetit: tarjotaan CloudFrontista.
  • Data engineering: raakadata-järvi (data lake), johon Airflow-DAGit kirjoittavat Parquet-tiedostoja.
  • Varmuuskopiot: ylimääräinen kopio tietokannan dumpeista, versioinnilla ja elinkaarisäännöillä.

Esimerkki: suojattu bucket

resource "aws_s3_bucket" "media" {
  bucket = "toni-devops-demo-media-eu-north-1"
}

resource "aws_s3_bucket_public_access_block" "media" {
  bucket                  = aws_s3_bucket.media.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_versioning" "media" {
  bucket = aws_s3_bucket.media.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "media" {
  bucket = aws_s3_bucket.media.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

S3-bucketit ovat yleisin syy tietovuotoihin, kun ne on tehty julkisiksi vahingossa. Pidä public_access_block aina päällä, ja jaa julkiset tiedostot CloudFrontin kautta.

12. CloudFront (CDN)

Mitä se on: Sisältöjakeluverkko (CDN). Välimuistittaa sisältöä palvelinten lähellä ympäri maailmaa ja tarjoaa HTTPS:n ilmaiseksi sertifikaatilla.

Liittyy muihin: S3 (alkuperä), ACM (sertifikaatti, pitää olla us-east-1), Route 53, WAF (palomuuri), Lambda@Edge.

Mihin sitä käytetään ja miksi

  • Nopeus: Next.js-staattiset sivut ja kuvat tarjoillaan lähimmästä pisteestä Suomessa.
  • Alkuperän suojaus: Origin Access Control (OAC) sallii CloudFrontin lukea S3:a, mutta ei julkista pääsyä bucketiin.
  • Kuorman vähennys: välimuistissa olevat pyynnöt eivät osu sovellukseen tai tietokantaan.

Esimerkki

resource "aws_cloudfront_origin_access_control" "media" {
  name                              = "media-oac"
  origin_access_control_origin_type = "s3"
  signing_behavior                  = "always"
  signing_protocol                  = "sigv4"
}

resource "aws_cloudfront_distribution" "media" {
  enabled             = true
  default_root_object = "index.html"

  origin {
    domain_name              = aws_s3_bucket.media.bucket_regional_domain_name
    origin_id                = "s3-media"
    origin_access_control_id = aws_cloudfront_origin_access_control.media.id
  }

  default_cache_behavior {
    target_origin_id       = "s3-media"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    compress               = true
    forwarded_values {
      query_string = false
      cookies { forward = "none" }
    }
  }

  restrictions {
    geo_restriction { restriction_type = "none" }
  }

  viewer_certificate {
    cloudfront_default_certificate = true
  }
}

# Bucket-politiikka: vain tämä CloudFront-jakelu saa lukea
data "aws_iam_policy_document" "media_cf" {
  statement {
    actions   = ["s3:GetObject"]
    resources = ["${aws_s3_bucket.media.arn}/*"]
    principals {
      type        = "Service"
      identifiers = ["cloudfront.amazonaws.com"]
    }
    condition {
      test     = "StringEquals"
      variable = "AWS:SourceArn"
      values   = [aws_cloudfront_distribution.media.arn]
    }
  }
}

resource "aws_s3_bucket_policy" "media" {
  bucket = aws_s3_bucket.media.id
  policy = data.aws_iam_policy_document.media_cf.json
}

Next.js-sovelluksen dynaamiset API-reitit eivät kuulu CloudFrontin S3-alkuperään. Ne ohjataan yleensä ALB:lle, jolloin CloudFrontiin lisätään toinen origin.

13. Route 53 ja ACM (DNS ja TLS)

Mitä se on: Route 53 on DNS-palvelu (nimipalvelin). ACM (AWS Certificate Manager) myöntää ilmaiset TLS-sertifikaatit, jotka uusiutuvat automaattisesti.

Liittyy muihin: ALB, CloudFront, API Gateway, S3-staattiset sivut.

Mihin sitä käytetään ja miksi

  • Oma domain sovellukselle: app.esimerkki.fi osoittaa ALB:lle tai CloudFrontiin.
  • HTTPS: selain ei varoita, ja hakukoneet suosivat salattua liikennettä.
  • Vaihdettava: DNS-muutos on yksi Terraform-muutos, ei manuaalista säätöä.

Esimerkki

data "aws_route53_zone" "main" {
  name = "esimerkki.fi"
}

resource "aws_acm_certificate" "app" {
  domain_name       = "app.esimerkki.fi"
  validation_method = "DNS"

  lifecycle {
    create_before_destroy = true
  }
}

# Validointitietue: ACM pyytää todistuksen DNS-tasolla
resource "aws_route53_record" "cert_validation" {
  for_each = {
    for dvo in aws_acm_certificate.app.domain_validation_options : dvo.domain_name => {
      name   = dvo.resource_record_name
      record = dvo.resource_record_value
      type   = dvo.resource_record_type
    }
  }
  zone_id         = data.aws_route53_zone.main.zone_id
  name            = each.value.name
  type            = each.value.type
  records         = [each.value.record]
  ttl             = 60
  allow_overwrite = true
}

resource "aws_acm_certificate_validation" "app" {
  certificate_arn         = aws_acm_certificate.app.arn
  validation_record_fqdns = [for r in aws_route53_record.cert_validation : r.fqdn]
}

resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.app.arn
  port              = 443
  protocol          = "HTTPS"
  certificate_arn   = aws_acm_certificate_validation.app.certificate_arn
  ssl_policy        = "ELBSecurityPolicy-TLS13-1-2-2021-06"

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.app.arn
  }
}

resource "aws_route53_record" "app" {
  zone_id = data.aws_route53_zone.main.zone_id
  name    = "app.esimerkki.fi"
  type    = "A"

  alias {
    name                   = aws_lb.app.dns_name
    zone_id                = aws_lb.app.zone_id
    evaluate_target_health = true
  }
}

Muista ohjata HTTP-kuuntelija (port 80) uudelleenohjaukseen HTTPS:lle tuotannossa. Kurssin ALB-esimerkissä HTTP on vielä päällä.

14. EC2 (virtuaalipalvelin, VPS-vaihtoehto)

Mitä se on: Virtuaalipalvelin. Saat täyden hallinnan käyttöjärjestelmään, mutta myös vastuun päivityksistä, palomuurista ja skaalauksesta. EC2 on AWS:n vastine VPS:lle.

Liittyy muihin: EBS (levy), Elastic IP, Auto Scaling, Systems Manager (ilman SSH:ta), VPC, IAM-instanssiprofiili.

Mihin sitä käytetään ja miksi

  • Kun tarvitset hallintaa: omat ajurit, pitkäkestoiset prosessit, GPU-laskenta (esim. paikallisen mallin ajo pilvessä).
  • Kun Fargate ei riitä: ohjelmat, jotka vaativat käyttöjärjestelmätason pääsyn.
  • Oppimisen kannalta: ymmärrät, mitä ECS ja Fargate abstrahoivat pois.

Esimerkki: EC2 Docker-isännäksi

data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]
  filter {
    name   = "name"
    values = ["al2023-ami-2023*-x86_64"]
  }
}

resource "aws_instance" "vps" {
  ami                         = data.aws_ami.al2023.id
  instance_type               = "t3.micro"
  subnet_id                   = aws_subnet.public[0].id
  vpc_security_group_ids      = [aws_security_group.app.id]
  associate_public_ip_address = true

  # Ajetaan kerran ensimmäisellä käynnistyksellä
  user_data = <<-EOF
    #!/bin/bash
    dnf install -y docker
    systemctl enable --now docker
    usermod -aG docker ec2-user
  EOF

  tags = { Name = "devops-demo-vps" }
}

Ei SSH-avaimia: käytä AWS Systems Manager Session Manageria, jolloin porttia 22 ei tarvitse avata ollenkaan. Tarvitset siihen instanssiprofiilin, jolla on AmazonSSMManagedInstanceCore-politiikka.

15. Lambda ja EventBridge

Mitä se on: Lambda ajaa koodia tapahtumien perusteella ilman palvelinta. Maksat vain ajoajasta. EventBridge on tapahtumaväylä, joka voi käynnistää Lambdan aikataulun (cron) tai muiden palveluiden tapahtumien perusteella.

Liittyy muihin: S3 (tiedostotapahtumat), API Gateway (HTTP), SQS, RDS Proxy, CloudWatch, ECR (kontti-imagena).

Mihin sitä käytetään ja miksi

  • Ajastetut tehtävät: päivittäinen ETL, joka hakee datan API:sta ja kirjoittaa sen PostgreSQL:ään tai S3:een.
  • Tapahtumapohjainen käsittely: tiedosto ilmestyy S3:een, Lambda käsittelee sen heti.
  • Kun kuorma on epätasainen: ei kiinteää kapasiteettia, joka seisoo tyhjillään yöllä.

Esimerkki: ajastettu ETL-funktio konttina

data "aws_iam_policy_document" "lambda_assume" {
  statement {
    actions = ["sts:AssumeRole"]
    principals {
      type        = "Service"
      identifiers = ["lambda.amazonaws.com"]
    }
  }
}

resource "aws_iam_role" "lambda" {
  name               = "daily-etl-role"
  assume_role_policy = data.aws_iam_policy_document.lambda_assume.json
}

resource "aws_iam_role_policy_attachment" "lambda_logs" {
  role       = aws_iam_role.lambda.name
  policy_arn = "arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole"
}

resource "aws_lambda_function" "etl" {
  function_name = "daily-etl"
  role          = aws_iam_role.lambda.arn
  package_type  = "Image"
  image_uri     = "${aws_ecr_repository.app.repository_url}:etl-latest"
  timeout       = 300
  memory_size   = 512
}

resource "aws_cloudwatch_event_rule" "daily" {
  name                = "daily-etl-schedule"
  schedule_expression = "cron(0 3 * * ? *)"   # joka päivä klo 03:00 UTC
}

resource "aws_cloudwatch_event_target" "daily_etl" {
  rule = aws_cloudwatch_event_rule.daily.name
  arn  = aws_lambda_function.etl.arn
}

resource "aws_lambda_permission" "allow_events" {
  statement_id  = "AllowEventBridge"
  action        = "lambda:InvokeFunction"
  function_name = aws_lambda_function.etl.function_name
  principal     = "events.amazonaws.com"
  source_arn    = aws_cloudwatch_event_rule.daily.arn
}

Data engineering -vinkki: Airflow ajaa DAG:it omalla infrastruktuurillaan, mutta yksinkertaiset ajastetut tehtävät voi siirtää Lambdaan. Lambdan 15 minuutin raja tekee siitä huonon raskaille erille, joissa Fargate (ECS scheduled task) on parempi.

16. CI/CD: GitHub Actions ja OIDC

Mitä se on: Automaattinen putki, joka testaa, rakentaa ja julkaisee koodin. AWS-puolella yhdistät GitHub Actionsin IAM-rooliin OIDC:n avulla, jolloin pitkäaikaisia AWS-avaimia ei tarvita lainkaan.

Liittyy muihin: ECR (kuvien työntö), ECS (deploy), IAM (OIDC-rooli), Terraform (infrastruktuurin apply), CodePipeline ja CodeBuild (AWS-natiivi vaihtoehto).

Mihin sitä käytetään ja miksi

  • Toistettava julkaisu: jokainen merge mainiin tuottaa saman prosessin ja saman tuloksen.
  • Ei salaisuuksia repossa: OIDC antaa putkelle väliaikaisen roolin, joka vanhenee automaattisesti.
  • Turvallisuus: rooli rajataan vain tiettyyn repositorioon ja haaraan.

Esimerkki: OIDC-luottamus ja rooli

resource "aws_iam_openid_connect_provider" "github" {
  url             = "https://token.actions.githubusercontent.com"
  client_id_list  = ["sts.amazonaws.com"]
  thumbprint_list = ["6938fd4d98bab03faadb97b34396831e3780aea1"]
}

data "aws_iam_policy_document" "gha_assume" {
  statement {
    actions = ["sts:AssumeRoleWithWebIdentity"]
    principals {
      type        = "Federated"
      identifiers = [aws_iam_openid_connect_provider.github.arn]
    }
    condition {
      test     = "StringEquals"
      variable = "token.actions.githubusercontent.com:aud"
      values   = ["sts.amazonaws.com"]
    }
    # Vain tämä repo ja main-haara saavat ottaa roolin
    condition {
      test     = "StringLike"
      variable = "token.actions.githubusercontent.com:sub"
      values   = ["repo:TONI_GITHUB_KÄYTTÄJÄ/devops-portfolio:ref:refs/heads/main"]
    }
  }
}

resource "aws_iam_role" "github_deploy" {
  name               = "github-actions-deploy"
  assume_role_policy = data.aws_iam_policy_document.gha_assume.json
}

Workflow-tiedosto GitHubissa

name: deploy
on:
  push:
    branches: [main]

permissions:
  id-token: write    # tarvitaan OIDC-tokeniin
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/github-actions-deploy
          aws-region: eu-north-1

      - name: Kirjaudu ECR:ään
        id: ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Rakenna ja työnnä image
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
          TAG: ${{ github.sha }}
        run: |
          docker build -t $REGISTRY/devops-demo:$TAG .
          docker push $REGISTRY/devops-demo:$TAG

      - name: Päivitä ECS-palvelu
        run: |
          aws ecs update-service --cluster demo-cluster --service devops-demo --force-new-deployment

Yllä latest-tagin sijaan käytetään commit-hashia, jolloin jokainen versio on jäljitettävissä. Tuotannon task definitionin image-tagi päivitetään Terraformilla tai ECS-deployn kautta.

17. Kokoava harjoitus

Rakenna kokonaisuus, jossa on seuraavat osat, ja pidä jokainen vaihe omassa Terraform-moduulissaan tai tiedostossaan:

  1. Backend (S3 + DynamoDB) ja provider.
  2. VPC, julkiset ja yksityiset aliverkot, Security Groupit.
  3. ECR ja Docker-kuva Django- tai FastAPI-sovelluksestasi.
  4. RDS PostgreSQL yksityisessä aliverkossa, salasana Secrets Managerissa.
  5. ECS Fargate -palvelu, ALB ja CloudWatch-lokit.
  6. Hälytys ALB:n 5xx-virheille.
  7. GitHub Actions OIDC:llä ja automaattinen deploy main-haaraan.

Tarkistuslista

KysymysVastaus, jonka pitäisi tulla mieleen
Miksi tietokanta on yksityisessä aliverkossa?Sitä ei voi tavoittaa internetistä, ja pääsy rajataan Security Groupilla sovellukseen.
Miksi ECS-tehtävällä on kaksi roolia?Execution role hakee imagen ja lokit, task role antaa sovellukselle oikeudet AWS-palveluihin.
Miksi tila on S3:ssa?Jaettu, salattu ja versioitu tila, jota voi lukita DynamoDB:llä.
Miksi OIDC on parempi kuin AWS-avaimet CI:ssä?Tokenit vanhenevat, eikä salaisuuksia tarvitse tallentaa repoon.
Mikä on Fargaten ja EC2:n ero?Fargatessa AWS hallitsee palvelimet, EC2:ssa hallitset itse käyttöjärjestelmän.

Seuraava askel: Kun tämä toimii, lisää Django-sovelluksesi /health/-päätepiste, sähköpostit SES:llä ja pidä kustannukset kurissa Cost Explorerilla. Devops-portfoliosi kannalta kokonaisuus, jossa on yksi Terraform-ajo, CI/CD ja hälytykset, on jo vahva näyte.

Kurssi on tarkoitettu oppimiseen. Muista tarkistaa palvelujen hinnat ja ominaisuudet AWS:n virallisesta dokumentaatiosta, sillä palvelut ja hinnat muuttuvat.
